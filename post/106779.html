clash漏洞，当心你的电脑中招！

https://www.nodeloc.com/t/topic/106779 · n/program
早间·09:33 |6 分 |14 评论 |by deity

OP（deity）警告 Sub-Store 本地服务（127.0.0.1:38324）存在被恶意网页 JS 远程执行命令的漏洞：本地无鉴权、CORS 放行、new Function 执行任意脚本，配合 child_process.execSync 下载木马。给出 4 条防护（开 auth token、不开陌生网页、不暴露 0.0.0.0、升级新版）。

原文摘录

OP（deity）10 小时前发帖：
对仍在用 clash 或 Sub-Store 的用户，务必注意以下漏洞。

攻击完整流程：
1. 用户打开攻击者控制的恶意网页
2. 网页内 JS 直接请求本机 http://127.0.0.1:38324
关键点：浏览器页面可访问本机回环地址，仅绑 127.0.0.1 不能阻挡网页 JS 发起请求。
3. Sub-Store 本地服务无身份认证，直接接收外部传入的请求，无需密码 token
4. 接口返回头带 Access-Control-Allow-Origin: *，CORS 放行，网页 JS 可读接口返回
5. 恶意网页发 POST /api/preview/sub，传入恶意脚本代码
6. Sub-Store 用 new Function() 动态执行传入脚本
7. 恶意脚本拿到 node 底层模块 require("child_process")
8. 使用 execSync() 在本机执行系统命令（whoami → certutil 下载木马 → 沦陷）

防护方案：
- 设置 Sub-Store 访问密码（auth token），开启接口鉴权；不要裸跑无密码本地实例
- 不要随便打开陌生网页；本机跑 Sub-Store 期间避免访问来历不明的站点
- 不把端口暴露公网；仅本地使用，不要 0.0.0.0 监听
- 升级到最新版本（该风险已在新版做限制）

本质属于本地服务被浏览器网页侧攻击，是很多 Node 写的本地桌面工具常见安全坑。简单自测（主要 Windows 端）：开 Sub-Store 节点后访问 http://127.0.0.1:38324 看是否可通。
