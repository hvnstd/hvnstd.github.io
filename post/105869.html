DeepSeek Harness 插件装之前，我现在会先检查这几件事

https://www.nodeloc.com/t/topic/105869 · n/ai
午间·16:21 |7 分 |10 评论 |by susu su

装 DeepSeek Harness 插件前先检查：1) 安装方式/包是否真实存在、有无 postinstall；2) 能安装成功比 Star 数重要；3) 是否碰 terminal/filesystem（风险分级）；4) credentials 存储与流向；5) 没发现风险≠安全；6) 最后才看功能是否值得装。

原文摘录

最近折腾 DeepSeek Harness（DSH）插件比较多，慢慢发现一个问题：「GitHub 上有这个插件」和「这个插件现在能正常装、适合装」完全是两回事。现在装陌生插件前会先看：1) 确认安装方式（npm 包是否真实存在、package name 是否写错、repo 是否还在、最近是否更新、是否需要额外 build、有无 postinstall/install script）；2) 能安装成功比 Star 数更重要（DSH 生态新，可能 package 已不存在/依赖版本对不上/build 出错/manifest 变化/新版本不兼容，最好临时环境先跑一遍 下载→依赖解析→build→plugin load）；3) 看是否碰 terminal（只读 API < 写入外部服务 < 文件系统 < Terminal/Shell，越往后越要看源码）；4) Credentials（存在哪里、是否本地读取、发送到哪个域名、日志是否输出、有无 telemetry，搜 process.env/fetch/axios/telemetry/analytics）；5) 没发现风险≠安全（只能说明没发现，不能推出经过安全审计）；6) 最后才看功能是否值得装（顺序反转为：功能是否真需要→项目还维护吗→能正常安装吗→需要什么权限→有无 install script/terminal/credential→再决定装）。
