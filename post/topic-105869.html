原文摘录

最近折腾 DeepSeek Harness（DSH）插件比较多，发现"GitHub 上有这个插件"和"这个插件现在能正常装、适合装"完全是两回事。装陌生插件前现在会先检查：

1. 先确认安装方式：看 README 是 npm package 还是 GitHub repository；额外确认 npm 包是否真存在、package name 是否写错、repo 是否还在、最近有没有更新、是否需要额外 build、有没有 postinstall/install script（install script 会在安装过程额外执行代码，至少要知道它在干什么）。
2. 能安装成功比 Star 数更重要：DSH 生态还新，有些插件 README 没问题但 package 已不存在 / dependency 版本对不上 / build script 出错 / manifest 格式已变 / 新版本 DSH 不兼容。最好放临时环境完整跑一次：下载安装 → dependency resolve → build → plugin load，能跑通再进正式环境。
3. 看它有没有碰 terminal：只调 API/读公开数据 与 可操作 terminal/filesystem 风险完全不是一个级别；Agent 场景下模型决定何时调用工具，权限边界宽则影响范围大。粗略分级：只读 API < 写入外部服务 < 文件系统 < Terminal/Shell，越往后越值得看源码。
4. Credentials 容易忽略：确认 credential 存在哪里、是否只在本地读取、会发到哪个域名、日志会不会输出、有没有额外 telemetry；源码不长时直接搜 process.env / fetch( / axios / telemetry / analytics 几分钟可知数据流向。
5. "没发现风险"不等于"安全"：自动只能判断有无 install script/terminal/credentials/异常依赖，没发现这些只能说明没发现，不能推出经过安全审计；Agent Plugin 权限大，最终还是要看源码和实际用途。
6. 最后才看功能值不值得装：顺序反转为 功能需要吗 → 项目维护吗 → 能正常安装吗 → 需要什么权限 → 有无 install script/terminal/credential → 再决定装。
