原文摘录

之前在这个节点发过一个求助帖（“有没有什么好用的开源的聚合邮箱”），想要一个能在 Serv00 上跑的、轻量的、聚合多个邮箱的方案。
翻了一圈：
Roundcube 太重，配置麻烦
一些开源项目要 Docker / 要 VPS
有纯 PHP 的，但大多只支持一个邮箱，或多邮箱支持要靠插件
Serv00 免费机也不适合跑常驻进程
一句话：
不需要 Docker，不需要 VPS，只要支持 PHP + IMAP 的虚拟主机就能跑。
（这里插一张暗色模式收件箱的截图）
把项目文件夹传到
。
走完 5 步：环境检测 → 建库 → 建管理员 → 加邮箱 → 完成。
，CPU / 内存占用都很低。
PHP 7.4+（推荐 8.0+）
Serv00 / 宝塔 / cPanel 都可以
MIT 协议，随便改随便用。
写的时候有意做了几个决定，说明一下：
虚拟主机用户申请数据库比较麻烦，SQLite 一个文件搞定，不用建库建用户。Serv00 上完全够用。
Serv00 免费机不允许常驻进程，
+
的长连接方案跑不了。用 Cron 每分钟轮询是唯一可行方案，延迟 ≤1 分钟。
有些聚合工具会把"取消订阅"的邮件直接从云端删掉。但万一误判，你就永久丢了那封邮件。我的方案是
——你去 Gmail/QQ 网页看，邮件还在。
目标用户是虚拟主机用户。做了 Docker 反而增加门槛。
如果在 Serv00 或其他虚拟主机上部署遇到问题，可以直接回帖或者提 Issue。欢迎 PR。
