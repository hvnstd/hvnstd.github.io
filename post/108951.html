，配套 Matt 的 Grill-me skill 使用，把任务交给 Codex 自动开发、验收和修复，现在也支持飞书进度通知。
项目地址：
我现在开发基本都是用
讨论自己工具的需求，再通过
、
拆成 GitHub Tickets。但在实际开发时，还有两件事需要不断手动跟进：
任务拆好了，仍然要逐个ticket推动开发，跟进修复，再处理 PR 。
Agent 开发的质量不够满足要求。即使Agent自己做过 code review，也经常有很多bug。
所以做了这个工具
它会按github上的ticket依赖顺序，自动逐个开发。每项任务完成后，单独调用一个 Codex Agent 做验收，实际运行功能、对照需求检查；发现问题交回开发Agent，修完再次验收。创建 PR、修复CI检查、关闭已完成的ticket，也包含在流程里。
所有ticket完成后，还会再整体检查以便完整功能。每个ticket单独做好，不代表拼起来就能正常工作。
运行中可以在命令行用
看当前任务，用
回看开发和验收记录。
之前想知道开发进行到哪一步了，还是得反复切回运行窗口。去忙别的事情，也可能没注意到任务已经停下来等人进行处理。
现在可以通过飞书看进度：哪项任务完成了、检查结果如何、是否需要人工处理，都有对应消息。卡片里也有 Issue 或 PR 的入口，方便回去查看。
通知有两种模式：
精简模式：只看重要进展、需要处理的事项和最终结果。
详细模式：还能看到每轮开发、验收和自动修复的过程。
欢迎大家可以试一试，star一下！
